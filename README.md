# Manoveir Trading CO — Website

Static informational site for **Manoveir Trading CO**, an IT services practice — staff
augmentation, software delivery, IT consulting and managed support for client teams.

Built with [Astro](https://astro.build) (`output: "static"`), plain CSS, and **zero client-side
JavaScript**. There is no backend, database or API — the site is a folder of HTML/CSS you can host
anywhere.

## Requirements

- **Node.js ≥ 22.12** (Astro 7 requires it; developed on Node 24). Pinned in `.nvmrc` and `engines`.
- npm ≥ 9.6.5

## Commands

```bash
npm install      # install dependencies
npm run dev      # dev server with hot reload → http://localhost:4321
npm run build    # typecheck (astro check) + build static output into dist/
npm run preview  # serve the built dist/ locally
npm run og       # regenerate public/og-image.png (only after a name/tagline/brand change)
```

> **`npm run preview` runs in the background.** Astro 7 daemonises it, so the command exits
> immediately while the server keeps running. Manage it with `npx astro preview status`,
> `npx astro preview logs`, and `npx astro preview stop`. If it picks port 4322 instead of 4321,
> a previous preview is still alive and serving a **stale build** — stop it first.

## Pages

| Route       | File                       | Contents                                                        |
|-------------|----------------------------|-----------------------------------------------------------------|
| `/`         | `src/pages/index.astro`    | Hero + desk illustration, services, why choose us, process steps |
| `/about`    | `src/pages/about.astro`    | Our story, at-a-glance facts, values, stats                     |
| `/it-services` | `src/pages/it-services.astro` | All four service lines, how engagements work             |
| `/contact`  | `src/pages/contact.astro`  | Email and the `mailto:` enquiry form                             |
| `/404`      | `src/pages/404.astro`      | Not-found page (`noindex`), links to every route                |
| `/robots.txt` | `src/pages/robots.txt.ts` | Generated so the `Sitemap:` line always matches the real domain |

These are real separate routes with a shared `BaseLayout`, not anchors on one page.
`sitemap-index.xml` / `sitemap-0.xml` are generated by `@astrojs/sitemap`.

## Editing content — start here

**[`src/config/site.ts`](src/config/site.ts) is the single source of truth.** Business name,
tagline, contact details, navigation, the four service lines, why-choose-us points, values and
stats live there. No page hardcodes a phone number or email address.

Feature and service `icon` values are **names in [`src/components/Icon.astro`](src/components/Icon.astro)**,
not emoji — add the glyph there first if you introduce a new service or feature.

### Contact details

No placeholders remain. `contact.email` in `site.ts` is **`hr@manoveirtrading.com`** — the footer,
the contact block, the `/contact` enquiry form (`mailto:`) and the structured data all use it.

The `TODO:` machinery is still in place for any future provisional value: prefix one in `site.ts`
and every page treats it as unfilled — it renders as quiet dotted-underline text with a short
user-facing note, the literal prefix is stripped from the output (see `displayValue()`), and the
enquiry form stays disabled while the email is pending. Deliberately quiet: an earlier version
shouted them in amber dashed boxes, which made the whole site read as unfinished.

### Adding your address, hours or a map

The site models **no street address, opening hours, map or customer testimonials** — publishing
invented or placeholder versions of those is what made it look unfinished, so they are absent
rather than faked. To reintroduce any of them:

1. Add the real value to `site.ts` (e.g. `contact.address`, `contact.hours`).
2. Render it where it belongs — `ContactBlock.astro` for the contact rows, `Footer.astro` for the
   footer column.
3. For local SEO, also add a component `postalAddress` (`streetAddress`, `addressLocality`,
   `addressRegion`, `postalCode`, `addressCountry`) plus `openingHoursSpec` in schema.org form
   (`["Mo-Sa 09:00-21:00"]`) and feed them into `businessSchema` in `BaseLayout.astro`. Google
   ranks a component address far better than one free-text line.
4. For a map, add a Google Maps *embed* URL and render an `<iframe>` on `/contact`; the CSP in
   `public/_headers` and `vercel.json` already allows `google.com` / `maps.google.com` frames.

### Images

The artwork is **hand-built SVG** — [`TechDesk.astro`](src/components/illustrations/TechDesk.astro)
in [`src/components/illustrations/`](src/components/illustrations/), used in the home hero, `/about`
and `/it-services`. It ships as a real drawing rather than a "photo goes here" box, scales to any
width and costs nothing to load.

If you would rather use a genuine photograph, drop it at `public/images/tech-desk.jpg` and swap
the `<TechDesk />` in [`src/components/Hero.astro`](src/components/Hero.astro) for an `<img>`.

## SEO & sharing

- **Per-page** `<title>`, meta description, canonical URL, Open Graph and Twitter card tags.
- **Share image** at `public/og-image.png` (1200×630), generated by
  [`scripts/generate-og-image.mjs`](scripts/generate-og-image.mjs) from the name, tagline and
  service list in `site.ts`. Committed to the repo — rerun `npm run og` only if branding changes.
- **`Store` structured data** (schema.org JSON-LD) in `BaseLayout`, which is what feeds Google's
  local results panel. It is built from `site.ts` and **omits any field still holding a `TODO:`
  placeholder**. With the real email in place the block is now published with a reachable contact;
  adding an address and hours (see above) is what will get the most out of it — then validate at
  [search.google.com/test/rich-results](https://search.google.com/test/rich-results).

## Design system

Theme is a **warm dark shopfront**: near-black walnut grounds, amber lamplight as the single
accent, cream text, with sage and terracotta appearing only inside the illustrations. All colours,
radii and shadows are CSS custom properties at the top of
[`src/styles/global.css`](src/styles/global.css) — change them there and the whole site follows.
Typography is Fraunces (h1/h2) + Inter (everything else) from Google Fonts, set in sentence case.

The visual language is deliberate and worth keeping consistent:

- **No gradients, no glows, no blur, no glassmorphism.** Surfaces are solid (`--surface`) with a
  flat 1px `--line` border. An earlier version leaned on a violet→cyan gradient, translucent cards
  and radial glows; it read as generic and was scrapped, so please don't reintroduce that vocabulary.
  (One scoped exception: `/it-services` re-themes its accent tokens to indigo/cyan and gives its
  cards a glass treatment inside its own `is:global` block — nowhere else.)
- **One accent, used sparingly.** Amber carries eyebrow labels, links, icons and the primary
  button, and nothing else; it is the single warm accent that ties the interface together.
- **Icons are drawn, not emoji.** Every glyph lives in
  [`src/components/Icon.astro`](src/components/Icon.astro) on a 24×24 grid with a 1.6 stroke and
  round caps, inheriting `currentColor`. Keep new glyphs on that grid or they will sit at a
  different optical weight. Icons appear in `.icon-tile` squares at 2.9rem — smaller than that and
  the finer glyphs turn to mud.
- **Restrained radii.** `--radius-sm` 8px for buttons and tiles, `--radius` 12px for cards,
  `--radius-lg` 18px for panels and figures. Nothing is a full pill.
- **Hover states change colour, not elevation** — cards shift from `--surface` to `--surface-2`
  and brighten their border. Nothing lifts, so reduced-motion users see the same affordance.
- **Grid and flex children carry `min-width: 0`.** Without it a single long word (an email address)
  refuses to shrink and widens the column past the viewport — `overflow-wrap` alone does not fix
  this, because it does not reduce an element's min-content width.

Global utility classes (`.container`, `.section`, `.masthead`, `.grid--3`, `.card`, `.icon-tile`,
`.btn`, `.panel`, `.facts`, `.trust`, `.stat`, `.field`, `.eyebrow`, `.todo`) live in
`global.css`; anything component-specific goes in that component's scoped `<style>` block.

## Notes

- **No CSS framework.** Plain CSS by design — do not add Tailwind.
- **Zero JS.** The mobile nav is a CSS-only checkbox toggle. Keep it that way; `dist/` contains no
  `.js` files at all.
- **Static-safe forms only.** The contact form uses `mailto:`; there is no form handler to break.
- **Do not remove `vite.build.cssTarget`** from `astro.config.mjs`. Without it the CSS minifier
  rewrites `@media (max-width: 52rem)` into range syntax that iOS Safari < 16.4 ignores, which
  leaves the mobile nav permanently expanded and overflowing.
- Accessibility: semantic landmarks, a skip link, `aria-current` on the active nav item, labelled
  form fields, visible focus rings, and `prefers-reduced-motion` handling.

## Deploying

`npm run build` writes everything to `dist/`. No Node runtime is needed in production — it is
plain files.

### 1. Set `SITE_URL` (do this first)

Canonical URLs, Open Graph tags, `sitemap-*.xml` and `robots.txt` are all derived from it. Without
it they fall back to `https://example.com`, which breaks link previews and search indexing.

Set it as an **environment variable on the host** (see `.env.example`) so going live needs no code
change:

```bash
SITE_URL=https://your-real-domain.example
```

### 2. Pick a host

**Netlify** — [`netlify.toml`](netlify.toml) is committed and covers build command, publish
directory and the Node version pin. Connect the repo; add `SITE_URL` under
*Site settings → Environment variables*.

**Cloudflare Pages** — set build command `npm run build`, output directory `dist`, and env vars
`SITE_URL` plus `NODE_VERSION=24`. It reads `public/_headers` natively; it ignores `netlify.toml`.

**Vercel** — auto-detects Astro. Add `SITE_URL`. Note `_headers` is *not* supported, so port those
rules to a `vercel.json` `headers` block if you need them.

**GitHub Pages** — needs a small Actions workflow, and if you deploy to
`username.github.io/repo-name` rather than a custom domain you must also set `base: '/repo-name'`
in `astro.config.mjs`. Ask before setting this up so the `base` is right.

**Plain nginx / Apache** — upload the contents of `dist/`. Directory URLs resolve natively
(`/about` → `/about/index.html`), so no rewrite rules are required. `_headers` is ignored, so
translate it manually — for nginx:

```nginx
error_page 404 /404.html;
add_header X-Content-Type-Options nosniff;
add_header X-Frame-Options SAMEORIGIN;
add_header Referrer-Policy strict-origin-when-cross-origin;

location /_astro/ {
  add_header Cache-Control "public, max-age=31536000, immutable";
}
```

### 3. Headers

[`public/_headers`](public/_headers) ships security headers (CSP, `X-Content-Type-Options`,
`Referrer-Policy`, HSTS) and long-lived caching for fingerprinted `/_astro/` assets. It is read
**only by Netlify and Cloudflare Pages** — every other host ignores it, so apply the equivalent
yourself.

The CSP allows Google Fonts, and a Google Maps iframe if you add one. If you add any third-party embed, widen it or
the browser will silently block the resource.
